## F13：从完整实体加载改为有限投影

原删除流程先加载全部关联 Token/Authorization 实体，再在一个事务中删除。Token 的载荷也随实体物化，因此内存分配随整图内容增长。首轮测量证明只读取 ID 和并发戳可减少载荷，但只读探针没有证明真正删除时能保留并发冲突和回滚，所以当时没有将其标为已修复。

现在每页最多投影 16 行 ID 与并发戳，按数据库 ID 顺序读取剩余数据的第一页；本页删除后再读取下一页，不使用会因删除而移动的 offset。先删 Token，再删从属 Authorization，最后删根实体。所有页仍在同一个 Serializable 事务内，最终仅提交一次。

未被调用方跟踪的行使用轻量实体及投影并发戳；已跟踪的实体保留原始戳，不能用刚查询的值覆盖。原始戳为 NULL 时显式以 `IS NULL` 删除并检查影响行数，避免 WDriver 的未使用参数绑定失败，同时保留 NULL 被其他连接改写后的冲突检测。成功页及时脱离跟踪，失败操作清理本次变更状态，防止后续 SaveChanges 重放失败删除。

最终完整轮次为 **30 通过、0 失败、0 跳过**，追加定向轮次为 **6 通过、0 失败、0 跳过**；覆盖 **32 个不同逻辑用例**，不是一次 36 项全套。早期全量在观察到 1 通过、3 失败后中止，修复 NULL 戳绑定问题后复验。用例覆盖根冲突、首中末页 Token 冲突、第二页 Authorization 冲突、页间取消、注入故障及 NULL 戳；独立连接确认整图回滚，同作用域后续 SaveChanges 写入零行，新作用域可以重试。

两种各含 35 个 Token 的大载荷图均跨三页，Application 图另外删除 17 个 Authorization（两页）。新增物化 LOB 为 0 字节，峰值跟踪从属实体为 16。Application/Authorization 样本耗时分别为 27,728/18,818 ms，进程级托管分配为 12,909,824/8,656,088 字节。这些是特定样本结果，不是堆峰值、网络流量或与旧流程的加速比。

原始证据位于 OpenIddict worktree 的 `.local/openiddict/results/paged-final.trx` 与 `paged-followup.trx`，具体方法见 [图删除验收](openiddict.md#图删除验收)。Astra High 独立审查与复审无未解决发现。

**剩余边界与后续路径：**分页约束新加载实体数量，不能约束整个事务的锁、日志或持续时间，也不会释放调用方预先加载的数据。若将来需要分批提交，必须先设计可恢复删除协议，并明确是否放弃当前整图原子性；不能只在页尾加 Commit。SaveChanges 拦截器现在按页触发，NULL 戳删除使用直接 DML，扩展方需按文档核对这些差异。提交应答丢失、HTTP OAuth/OIDC 流程尚未验收。

## F14：用独立令牌表示一次领取

原版 10.1.1 使用 UpdatedAt 作为竞争快照，又把节点当前时钟写回 UpdatedAt。时钟等值或回退时，旧快照可能继续匹配，两个节点均能领取同一任务。首轮仅证实了重复领取，未启动处理器，不能把当时的证据描述成已重复执行。

直接换上游版本没有形成已验证的解决路径：原会话检查了 10.4.0 发布程序集及 10.5.1 发布包对应源码；后者虽引入令牌，但领取更新仍有时间戳谓词，并涉及许可条件和存储升级。本轮没有把未验证的升级视为修复。候选版本的来源与具体边界见 [TickerQ 文档](tickerq.md#候选版本)。

实际实现基于 10.1.1 固定提交 `b2684f41a1c22f09e05cbac087c117751bd3e78c`，补丁随仓库保存。每次领取生成新 ClaimToken，并以旧令牌与状态作原子更新条件；执行入口、续期、释放和完成核对当前持有者与令牌。ClaimStarted 防止同一领取重复进入处理器，改期、接管、重启和同 ID 重建也会使旧令牌失效。父子链将根令牌传递给后代，子行变更在同一事务内锁定并校验根领取。启动恢复在播种与调度之前完成，避免清理本次启动刚产生的领取。

默认适配包引用三个同版本受控包：`W.TickerQ.Core`、`W.TickerQ.Utilities`、`W.TickerQ.EntityFrameworkCore`，版本均为 `10.1.1-dameng.1`。程序集名和命名空间沿用上游，包内保留许可证；构建从固定源码应用补丁，源生成器使用官方 10.1.1 发布件。补丁包必须与原版包整体替换，构建目标拒绝混装。维护补丁时应提升版本，不能覆盖已分发的同版本包。

**升级步骤：**先停止该 schema 上所有原版调度器和写入方；在应用自己的迁移历史上生成增量迁移，为 TimeTickers 增加带默认值的 ClaimToken 和 ClaimStarted；确认旧数据与三个补丁包一致后启动新节点。禁止原版和补丁版同时写同一 schema。示例迁移与命令见 [注册与迁移](tickerq.md#注册与迁移)。

原版播种和增量迁移各 **1 通过、0 失败、0 跳过**，独立 SQL 确认保留旧任务、周期定义、失败实例、请求和异常。最终完整轮次 **14 通过、0 失败、0 跳过**，其中 13 项实库测试、1 项程序集核验；覆盖等值/回退时钟、接管、旧持有者写回拒绝、真实处理器、链执行/跳过、启动播种、同节点重启、改期和同 ID 重建。首轮有一项 WDriver 绑定失败，修正后两轮完整回归均通过。最终证据为 TickerQ worktree 的 `.local/tickerq-f14/results/{seed-final,migration-final,fenced-final}.trx`。

测试进程对三个实际加载的 DLL 与本轮包内 DLL 逐一比对 SHA-256。Astra High 审查及复审覆盖启动顺序、改期、陈旧令牌及构建来源，最终无阻断发现。

**剩余边界与后续路径：**时间仍用于调度和超时资格，补丁不承诺消除时钟偏差的所有影响。运行中任务仍依赖同节点启动恢复，没有新增跨节点定期回收；已发生的外部副作用无法因令牌失效而撤销，业务必须采用幂等键或自己的事务边界。根任务终止后崩溃的后代恢复、跨进程链续跑、多机进程终止、Redis、Dashboard、自定义实体和共享 context 未验收。进一步扩展应以这些场景的故障注入和迁移回归为前提，不能宣称 exactly-once。

## 隔离与主分支集成

两个原会话继续使用各自独占的用户/schema、随机凭据及表空间。TickerQ 为旧数据迁移另建隔离分配，保留先前分配；OpenIddict 核验自身当前分配归属。回执权限为 0600，凭据和端点不进入源码或本文。主分支集成阶段不与库会话并发运行同一夹具。

根构建与包验证入口扩展为重建三个补丁包，再生成四个适配包。每轮补丁构建使用新 staging 和新缓存，将 `W.TickerQ.*` 精确映射到本轮源，逐字节核对 Core/EF 实际恢复的 Utilities nupkg；全部成功后才替换输出源。随后解决方案再以独立缓存构建。这样既保留外部依赖缓存，也避免旧同版本补丁包掩盖源码变化。

主分支 `scripts/verify-packages.sh --negative-checks` 已通过：8 项策略测试、解决方案和 6 个 provisioner 编译、7 个包、2 个独立消费者，以及错误源、Newtonsoft 降级、原版 TickerQ 混装三个预期失败检查。报告为 `artifacts/package-validation/20261108T015530Z-c653c0fd/report.json`，记录了每个包及 DLL 的 SHA-256，并确认源码构建恢复的补丁包来自本轮产物。该入口未读取数据库凭据、运行 provisioner 或连接数据库。

普通 `scripts/build.sh` 入口也通过，证据为 `.local/builds/20261108T015636Z-70e62d36/solution.log`。主分支重新生成的三个 TickerQ DLL 与最终实库测试 worktree 的包内 DLL 逐字节一致，核对记录为同一包验证目录下的 `tested-worker-assemblies.json`。

主会话另由 `gpt-6-astra` High 对根构建流程和最终证据独立复审，核对策略测试、包来源、三个负例、普通构建及两库原始 TRX，无未关闭的 P1/P2。
